## 2026-11-24 — 학생 흐름의 뼈대와 듣기·읽기 활동

> 첫 화면을 학생 입장 화면(학급 코드+번호)으로 바꾸고, 단원 목록 → 단원 화면 → 듣기·읽기 활동을 만들어 줘. 듣기는 단어·어구를 듣고 뜻 고르기, 질문을 듣고 대답 고르기(다시 듣기·천천히 듣기). 읽기는 질문-대답 잇기, 단어-뜻 잇기, 문답 순서 맞추기. 결과는 기기에 쌓고, 디자인은 AI 기본값에서 벗어나게(차분한 2색+회색, 왼쪽 정렬, 큰 글씨·큰 버튼).

- 파일을 나눔: `css/style.css`, `js/app.js`(주소 #/ 로 화면 전환), `js/data.js`, `js/speech.js`, `js/store.js`, `js/ui.js`, `js/activities/listen.js`·`read.js`·`result.js`
- 문항은 `units.json`의 핵심 표현(의사소통 기능, 주요 표현 연습, 신출 어휘, 단원 어구)만으로 그때그때 만듦. 교과서 대화문·읽기 글은 쓰지 않음
- 각 문항 결과(unit, skill, level, itemId, correct, answer, 시각, 학급 코드, 번호)를 `localStorage`의 `er5.attempts`에 쌓음. `sent:false`는 나중에 Supabase로 보낼 표시
- 화면을 headless Edge로 직접 눌러 보며 확인하는 도구 `tools/capture.mjs`를 만듦(콘솔 오류도 검사)
- 확인하다 고친 것
  - 9단원에서 "안경"과 "유리, 안경(glasses)"이 한 문제의 보기로 함께 나와 정답이 둘처럼 보임 → 철자나 뜻이 겹치는 단어는 같은 문제에 넣지 않게 함

  - 화면에 "null", "[object HTMLUListElement]" 글자가 보임 → 화면 그리는 도우미(`mount`)가 빈 값과 목록을 걸러 넣게 고침

## 2026-11-25 — 웨일북 점검: 소리 끊김, 문제와 소리 불일치, 어색한 발음

> 단어가 끝까지 안들려. 중간에 끊기듯이 멈춰.
> 문제와 보기가 달라. 그리고 발음이 어색해서 학습자가 오류를 학습할 수 있어.

- 원인으로 본 것: 크롬 계열에서 읽는 중인 발화 객체가 정리되면 소리가 중간에 멈춤, `cancel()` 직후 바로 읽으면 잘림, 앞 문제 소리가 다음 문제에서 늦게 나올 수 있는 구조
- 고친 것(`js/speech.js`, `js/activities/listen.js`): 발화 객체를 붙잡아 둠, 멈춘 뒤 잠깐 쉬고 읽음, 단어 끝에 마침표, 가장 마지막에 부른 소리만 냄, 오래된 듣기 화면은 그리지 않음, 자연스러운 목소리 우선 + 목소리 이름 표시
- 점검: 듣기 8문제마다 실제로 읽은 문장과 화면 문제를 대조 → 8/8 일치, 화면을 빠르게 오가도 문제 화면 1개
- 남은 고민: 브라우저 목소리는 기기마다 달라 발음 품질을 보장할 수 없음 → 미리 만든 원어민 수준 음성 파일로 바꿀지 사용자와 정하기로 함
- 전/후 화면: `screenshots/03-voice-before*.png` → `03-voice-after*.png`

## 2026-11-25 — 말하기·쓰기 활동과 수준별 단계 (예약 작업)

> 말하기·쓰기 활동과 수준별 단계: 원어민 음성 듣기 → 따라 말하기(음성 인식이 있으면 단어별 색 표시, 없으면 녹음 → 번갈아 듣기 → 스스로 평가), 철자 빈칸 채우기와 단어 카드 문장 만들기(터치로 쉽게), 진단 5문항 → 기초/기본/도전 추천, 기초는 힌트(첫 글자, 한국어 뜻, 천천히 듣기)를 더 줌, 학생이 단계를 직접 바꿀 수도 있게.

- AI가 만든 것
  - `js/activities/speak.js`: 음성 인식(en-US, 후보 5개 중 가장 잘 맞은 것) / 녹음(MediaRecorder, 단어 5초·문장 9초면 저절로 멈춤) / 녹음도 안 되면 스스로 평가만. 인식이 잘 안 될 때 녹음 방식으로 바꾸는 버튼(기기에 기억)
  - `js/compare.js`: 단어별 비교(순서를 지키는 가장 긴 공통 부분). 줄임말·숫자 말을 같게 봄
  - `js/activities/write.js`: 글자 조각 빈칸 채우기, 단어 카드 문장 만들기, 도전은 직접 입력
  - `js/activities/diagnose.js`, `js/level.js`: 진단 5문항(듣기 2·읽기 1·쓰기 2), units.json의 level 태그로 단계별 문항 고르기
  - 단원 화면에 "내 단계" 상자. 기록(`er5.attempts`)의 level에는 그때 학생의 단계를 넣고, 스스로 평가는 selfRating에 넣음
- AI가 정한 것(사용자가 없는 예약 실행이라 스스로 정함)
  - units.json에는 basic(어휘·어구·의사소통 기능)과 core(주요 표현 연습·언어 형식) 태그만 있어서, 도전 단계는 "core 문장을 힌트 없이 전체로"로 만듦(작업규칙의 저작권 항목과 같음)
  - 기초 단계에서 문장이 모자라는 단원(8·10단원)은 core 문장으로 채우되 힌트는 기초대로 줌
  - 철자 입력은 키보드 대신 글자 조각 누르기(기초·기본). 도전만 직접 입력
  - 진단 정답은 길게 알려 주지 않음(단계만 정하는 용도). 건너뛴 말하기 문제는 기록하지 않음
- 확인하다 고친 것
  - "They're twenty thousand won."을 인식기가 "they are 20,000 won"으로 적으면 절반만 맞게 나옴 → 여러 단어로 된 숫자와 줄임말을 합쳐 비교
  - 시각을 "330"처럼 붙여 적는 경우 → "3 30"으로 나눠 비교
  - 도전 단계의 섞는 카드에 "8" 같은 숫자가 나옴 → 같은 단원 문장의 영어 단어만 씀
  - 기초 단계 쓰기 문장이 1개뿐인 단원이 있어 문제 수가 4개가 됨 → 기본 문장으로 채움(5개 단원 × 3단계 × 30번 만들어 문제 수·보기 중복 0건 확인)
- 점검: headless Edge에서 가짜 음성 인식·가짜 마이크로 인식 결과 색 표시, 녹음 → 스스로 평가, 마이크 거부 알림, 진단 → 추천 → 단계 저장, 쓰기 기초·기본·도전, 결과 화면까지 눌러 봄. 콘솔 오류 없음

## 2026-11-27 — 학생 스스로 피드백과 보충 학습 (예약 작업)

> 학생 스스로 피드백과 보충 학습(필수 요구사항): 결과 화면에 영역별 정답률 막대, "잘한 점 / 더 연습할 점"을 규칙으로 생성(쓰기 50% 미만이면 철자 연습 권유), 스스로 평가(알아요/조금/어려워요) 저장. 오답 노트(단원·영역별, 다시 풀기). 보충 학습 버튼(틀린 문항과 같은 표현을 한 단계 쉬운 형태+힌트로, 다 맞히면 "다시 도전"). 첫 화면에 "오늘 할 일"(가장 약한 영역·단원, 이어서 하기). 빈 상태 안내.

- AI가 만든 것
  - `js/feedback.js`: 영역별 정답률, 잘한 점·더 연습할 점 규칙, 기록의 문항 번호(itemId)로 원래 표현 찾기, 오답 노트(문항마다 마지막 기록이 틀리면 남음), 오늘 할 일 계산, 정답률 막대
  - `js/activities/result.js`: 결과 화면을 점수 → 스스로 평가 → 잘한 점·더 연습할 점 → 보충 학습 버튼 → 단원 영역별 막대 → 다시 볼 것 순으로
  - `js/activities/remedial.js`: 보충 학습(쉬운 형태+힌트)과 다시 풀기(원래 모양, 힌트 없음)
  - `js/app.js`: `#/notes`(오답 노트), `#/fix/easy|retry/단원/영역`, 단원 목록 위 "오늘 할 일", 단원 화면에 "이 단원에서 다시 풀 문제"
  - `js/store.js`: 스스로 평가를 `er5.reflections`에 저장(sent:false, 11/29 서버 전송 때 함께 보냄)
- AI가 정한 것(사용자가 없는 예약 실행이라 스스로 정함)
  - 진단과 보충 학습(쉬운 문제)은 정답률에 넣지 않고, 오답 노트 "다시 풀기"는 넣음. 보충 학습만 맞혀서는 오답 노트에서 빠지지 않고 "보충 학습 맞힘 · 다시 풀기로 확인" 꼬리표만 붙음
